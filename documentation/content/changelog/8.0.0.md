# 8.0.0

JOID 8.0.0 compared with 7.0.1. Every package moves to `dev.joid`, JOID is released under the [Apache License 2.0](../getting-started/introduction.md), and fonts, resources and state are rebuilt. This page lists the breaking changes by area, then a [migration checklist](#migration-checklist), the new features and the fixes.

## Highlights

- **Reactive setters**: every setter of every node, effect and text takes a value or a `Supplier`. An expression that reads signals, `text(Text.create("Clicks: " + this.clicks.get(), info))`, is followed. See [Signals and State](../concepts/state.md).
- **One property per setter**: `color(c).hoveredColor(h)`, `x(...).y(...)`, `borderColor(c).borderStroke(2D)`.
- **Fonts from `.ttf`/`.otf` files**, with families, CSS weights, kerning, markup, text effects and pixel-art bitmap fonts. See [Text and Fonts](../concepts/text.md).
- **Media**: GIF, APNG, WebP, SVG and transparent WebM behind one playback API. An unreadable resource fails instead of throwing. See [Images and Media](../concepts/media.md).
- **Text fields with a value model**: `accept(...)`, `onChange((field, text, value, valid) -> ...)`, commit on Enter or blur. See [TextFieldNode](../nodes/input/text-field.md).
- **Browser-like mouse**: one target per event, bubbling to the parents, `interactive(false)`, system cursors. See [Input](../concepts/input.md).
- **One event system**: every listener takes a single event object; `handleX` sees the raw input and can `consume()` it, `beforeX` can `cancel()` an action, `onX` reports what happened; five priorities plus `MONITOR`; nodes, UIs, shortcuts, tasks and tweens share it. See [Events](#events).
- **`UIView`, overlays and interface scale**; pixel-exact rendering and smooth rotated edges on every backend.
- **Self-contained jars**: JavaCV, JSVG, TwelveMonkeys, and a relocated ASM, Gson, Guava, Commons IO and Commons Lang are embedded; no type of these libraries is left in the API; the FFmpeg natives of the running platform are downloaded once, at the first video or when `VideoNatives.install()` asks; prod jars hold no dev tool.

- The 1920×1080 canvas keeps a uniform scale at any window ratio (16:10 was stretched); the extra space goes to the anchor side. Fill it with `getView().getVisibleWidth/Height()` or `getViewX/Y/Width/Height()`.
- The zoom is clamped to `[0.1, max(1, 1 / interfaceScale)]`, written back into a bound signal, and kept on resize and when the UI opens again (`load(width, height)` keeps the current zoom).
- UIs are ordered by `zindex`; the top UI is the first active and visible one, so an inactive or hidden UI no longer takes the mouse from the UIs below.
- Escape goes to a closeable UI first (nodes, shortcuts, `keyPressed`, focused field); the UI closes only if nothing consumed it. A focused field takes the first Escape and loses its focus, so a second Escape closes the UI; `handleKeyPressed(event -> event.consume())` keeps the UI open.
- `JOID.close(ui)` and `close(ui, true)` do nothing for a UI that is not open: no `beforeClose`, no `onClose`, no dispose.
- A closed UI runs `init()` again when it opens again: its nodes are built anew, as after a reload, and its `LOCAL` stores start over; keep what must outlive it in a `GLOBAL` or `PERMANENT` store.
- Overlays draw below the screens unless `aboveScreens = true`; the order is the overlays below the screens, the UIs, then the overlays above, each group by `@UIData(zindex)`. Only `isOverlayHidden()` of the bridge hides an overlay (`always = true` keeps it).
- `UIBridgeRegistry.frame()` clears the window once per frame with the background of the lowest bridge (the first drawn) instead of the highest.
- `@UIDataScale(active = false)` keeps the interface scale at `1` everywhere (`UIDataScaleObject.apply(...)` returns `1`).
- A transition given with `setTransition(...)` stays when the popup data changes later.
- An exception thrown by the `update()` of a UI or of a node, or by the input code of a UI (`mousePressed`... of its nodes), prints `[JOID] The update of MenuUI failed (...), the next updates still run: ...` or `[JOID] The mousePressed of MenuUI failed (...), the next inputs still run: ...` once per cause, and the frame goes on.
- Ctrl+Shift+R (Shift+F5) now replaces the UI with a new instance (`UI.renew()`); Ctrl+R (F5) still reloads `init()`.
- UI data changed at runtime (`getData()`, `getPopup()`, `getDebug()`) applies on the next frame and survives a reload.
- `@UIData(background)` defaults to `false`: a UI no longer dims the window behind it.
- `UI.getCurrent()` is the UI whose code runs, not only during `init()`: also during `update()`, drawing, inputs, `reload()` and the callbacks of its nodes. A UI opened from another one gives the outer UI back once its `init()` ends, even if it throws.
- The listeners a UI registers in `init()` (or later) are removed before each new `init()` (`reload()`); those registered in its constructor stay. `StackUIBridge` prints a dev warning when a screen refuses to close and the new screen is not opened.
- `JOID.inst().load()` prints one line, `[JOID] 8.0.0 loaded in dev mode, data in <folder>, cache in <folder>` (`in dev mode`, `in demo mode` or `in dev and demo mode` only when they are on), instead of the ASCII banner and its parameter list.
- `IIndexedList` (`getNodeList()`, `getDrawList()`, the UIs of a bridge) keeps its z-index order by itself: a `zindex(...)` or `@UIData` z-index changed after insertion applies at the next ordered read (`ordered()`, `reversed()`, iteration, `get(...)`), without `sort()`.
- Every line JOID prints starts with `[JOID] `, in English: errors and warnings on the error output, information on the standard output. A warning that can come back on every frame (a setter value that cannot apply, a `watch(...)` that throws, a bridge draw that throws, a tween update that throws) prints once with its stack trace. The profiler prints one line, `[JOID] MenuUI loaded in 1.23ms`, `[JOID] MenuUI reloaded in 1.23ms` or `[JOID] MenuUI took 20.00ms to draw a frame, more than the 16.66ms of 60 fps`, instead of the `####` banners. Numbers and case changes in the messages and the dev panel use `Locale.ROOT`, so they read the same on every machine.

- A literal `null` is ambiguous between the value and `Supplier` setters: `hoveredColor((Color) null)`.
- Node setters return the declaring class: call the setters of the node class before those of `Node` (`x`, `visible`...), or add a type witness, `.<RectNode>color(...)`.
- The setters of `ProgressNode`, `ModelNode` and `ModelViewerNode` are `final`; the lifecycle and event methods of built-in nodes (`draw`, `mousePressed`, `keyPressed`...) are no longer `final`.
- `aspectRatio(r)` always means `width = height * r`; `0` is ignored.
- `CircleNode` draws the largest centered circle that fits its bounds.
- Every listener of a type runs, by priority then in insertion order, until one consumes or cancels the event; `MONITOR` listeners always run last.
- `append` moves a node out of its previous parent. `fireDetach()` ends drag, hover, focus, signal subscriptions and effect `detach`; `onMount` runs again on reattach and a `ResourcePlayerNode` restarts.
- `enabled(false)` disables the children; hidden and disabled nodes receive no input.
- `onScrollAtEnd` fires once, when the scroll rests at the end; `onScrollToEnd` is the early signal, when the target reaches the end; `onScroll` fires when the target moves. All three give the axis, the previous offset and the offset (`NodeScrollEvent.Post`).
- The position and the scroll of a node follow the rule of the values the user changes. `scrollX(...)`/`scrollY(...)` take a start value or a writable `Signal` (both ways); `x(...)`/`y(...)` keep a value, a lambda or a `Signal` (layout), but a `DraggableType.MOVE` drag on a node whose `x` or `y` is computed (lambda, signal that cannot be written, followed expression) throws `IllegalStateException` in either order. A `MOVE` drag, the wheel, the scrollbar and the auto-scroll of a `ReorderableFlexNode` write into the bound signal. `move(x, y)` and `scrollTo(x, y)` act like the user: refusable by `beforeMove` (`NodeChangeEvent.Pre<T, Point>`) and `beforeScroll` (`NodeScrollEvent.Pre`, one per axis). `onMove` and `onScroll` fire on every change once the node is in a UI; a `COPY` drag moves its ghost only and fires no `onMove`. The drag events (`beforeDragStart`, `onDragStart`, `onDrag`, `beforeDragDrop`, `onDragDrop`, `onDragSnap`) are unchanged. A scroll offset is `0` or negative; given before the node is attached it waits for the first layout, then it is clamped to `-getMaxScrollX/Y()` and written back into a bound signal.
- `getUi()` during `init()` returns the UI, but `hasUi()` stays `false` until the node is loaded.
- `ReorderableFlexNode` keeps the z-indexes of its children, fires `beforeReorder`/`onReorder` only on a slot change (`getCurrentIndex()` in `beforeReorder` is the index before the move), and gives the dragged child its own `beforeDragStart`, `onDragStart`, `onDrag`, `beforeDragDrop` and `onDragDrop`: `isDragging()` is `true` on the child during the drag, a refused start leaves the list still, a refused drop sends the child back to its first slot.
- A disabled node is hovered: `isHovered()` follows `UI.getHoveredPath()` only, its hover events, tooltip and cursor apply, but its hover animator (`hoverValue`) stays down, so no hover color; inputs stay blocked by `enabled`.
- `ModelViewerNode` turns with the left button only. `onClick` and the behaviors of the built-in nodes (checkbox, toggle, selector, slider and its thumb, scrollbar) take the left button only; read other buttons with `handleMousePressed(event -> event.getButton())`.
- `ResourceNode`, `ResourcePlayerNode`, `ChartNode` and `RadarChartNode` wait like `wait(...)`: for their resource, or for their axes and data. They draw the default skeleton of every node until then, fire `onMount` once ready, and a parent sees them as not mounted. A container draws only the skeletons of its children.
- `FlexNode`, `GridNode`, `ReorderableFlexNode`, the slider and the scrollbar place a child with a layout offset (`getLayoutX/Y()`) added to its own `x`/`y`: a position given to a child (value or `Supplier`) stays. A flex or grid with an overflow keeps its size and can scroll; without overflow it still fits its children, and a `GridNode` created with a height of `0` always fits its rows. `ABSOLUTE` children are neither placed nor counted; a hidden child is neither placed nor counted, and takes its slot again before it is drawn.
- The scroll of a node moves its children through `getShiftX/Y()`; `ABSOLUTE` children no longer count in `getMaxScrollX/Y()` and do not scroll.
- `copy()` follows like the original: the suppliers of its setters, the signals its controls are bound to, its `watch(...)` (without running them at once). The copy has no parent. A node built from other numbers, booleans or enums (`CircleNode`, `FlexNode`...) is copied through its first such constructor.
- The ghost of a `COPY` drag is a copy without listeners, with the parent of the original; its links run from the start of the drag to the drop.
- `effect(...)` on an attached node calls `init` and `detach` on the effect it replaces; `removeEffect(...)` and `clearEffects()` call `detach`; every effect is initialized when the node loads, even one `shouldApply` skips. A replaced `scrollbar(...)`, `skeleton(...)` or slider `thumb(...)` is detached.
- A node hidden under the mouse ends its hover and the hover of its children: `onHoverEnd`, hover color, tooltip and cursor.
- `hoverValue(...)` and the veil of a popup stay between `0` and `1` when the animator overshoots (`BACK_OUT`, `ELASTIC_OUT`).
- `ReorderableFlexNode.getChildIndex(...)` gives the slot of the drag order while a child is dragged, and the own offset of each child stays during the drag.
- `copy()` throws `IllegalStateException` (was `RuntimeException`) naming the field it cannot set or the constructors it looks for. A slider value outside its options names the value and the options; `data(...)` or `remove(...)` on a chart without X axis names the chart and the data.
- The `x`/`y` of a hover element is its top-left corner from the mouse (`follow`), the UI origin (`fixed`) or the hovered node (`relative`): it no longer rises by its own height, so give a negative `y` to keep a tooltip above. It stays inside the UI on all four edges.

- **Three prefixes**: `handleX` receives a raw input (press, release, drag, wheel, key, character) before the node's own behavior and can `consume()` it; `beforeX` is asked before an action and can `cancel()` it, the action and its `onX` are then skipped; `onX` tells what just happened and has no verb. `onClick` keeps its name and still takes the click.
- **Order of an input in a node**: children with `zindex >= 0` (front first), the node's `handleX` listeners, its own behavior (click of `onClick`, controls, scroll, typing, drag start), children with `zindex < 0`, then its `MONITOR` listeners. In a UI: its nodes, its `handleX` listeners, its shortcuts and defaults (zoom, dev keys), its `MONITOR` listeners; a `Shortcut` with `overrideFocus(true)` runs before the nodes. An input nobody consumed goes to the UI below, then to the host; Escape closes the UI only if nobody consumed it.
- **Consumed inputs**: once an input is consumed, the next `handleX` listeners and behaviors are skipped, the built-in behaviors still see `isConsumed()` (a field loses its focus, a selector closes), and `MONITOR` listeners always run. A parent cannot catch the input of its children in `handleX`: use `enabled(false)` or `interactive(false)`.
- **Priorities** order the listeners of one step of one node or UI, never the tree. `MONITOR` listeners run last, even for a consumed or cancelled event, and only read it: `consume()` or `cancel()` there throws `IllegalStateException`.
- **Refusals only for the user**: `beforeChange` runs only for a change made by the user (click, drag, typing) or `change(value)`; a bound signal, a setter (`checked`, `value`, `text`...) and `values(...)` always apply and still fire `onChange`. The same goes for every value an interaction changes, each with its gesture: `beforeMove`/`move(x, y)`, `beforeScroll`/`scrollTo(x, y)`, `beforeFocus`/`focus()`, `beforeBlur`/`blur()`, `beforeCursorMove`/`moveCursor(position)`, `beforeOpen`/`open()` and `beforeClose`/`close()` (selector), `beforeChange`/`change(zoom)` and `beforeRotate`/`rotate(yaw, pitch)` (model), `beforeZoom`/`zoomBy(delta)` (UI). The main value of a control keeps `beforeChange`/`onChange`; the other values are named after their gesture.
- **Isolated failures**: a listener that throws prints `[JOID] The onChange listener of SliderNode in MenuUI failed (...), the other listeners still run: ...` once per failure, and the next listeners still run; a failing `beforeX` listener does not cancel.
- Notifications (`onDetach`, `onInit`, `onWatch`, `onChildAppend`, hover, draw, scroll, drag progress) can no longer stop what they report; `onHoverStart`/`onHoverEnd` run once `isHovered()` changed.
- A node waiting for `wait(...)` sends its input only to its skeleton.

- An animator runs by itself once `start()` is called from UI code (`init()`, `update()`, inputs, node callbacks): JOID advances it at the start of every frame, before the UIs update, until its timeline ends, `clear()`, a new `sequence(...)`, or it is garbage collected (`isAutomatic()`). Started anywhere else, it still needs `update()`. The automatic animators advance once per frame, whatever the number of bridges: in `BridgeHandler.UI.frame()` (`backend.frame()`) or `UIBridge.frame()`, never in `UIBridge.update()`; a host that calls `update()` and `draw()` on its bridges itself calls `BridgeHandler.UI.fireFrame()` first. An animator that throws prints `[JOID] The update of TweenAnimator failed (...), the other animators still run: ...` once per cause and the frame goes on.
- `animate(animator)` no longer advances the animator: it subscribes the node, and `onAnimate` fires before the node's `update()` when the value differs from the last one it saw, hidden or not; `removeAnimator(...)` and detaching the node unsubscribe it. Drop the `animate(...)` calls that only kept an animator moving.
- An automatic animator keeps advancing while its node or UI is not drawn, so it no longer jumps to catch up when it shows again.
- `TweenAnimator` is a read-only signal: it notifies its subscribers, `map(...)` and the expressions that read it only when its value changes, inside `update(...)`, so nothing is recomputed once the animation ends. A setter reads it like any signal: `width(60D + 260D * size.get())` replaces `width(() -> 60D + 260D * size.getValue())`, and transitions expose the same signal through `getAnimator()`. Two animators are equal only when they are the same object.
- Tween events are notifications of the event system: `onStart` once, after the delay; `onIterationStart` and `onIterationEnd` for each play of a repeat or each way of a yoyo; `onComplete` at the end; the `onReverse...` events only when the time goes backward. A timeline sends its own events, after those of its children. A listener that throws prints `[JOID] The onComplete listener of Timeline failed (...), the other listeners still run: ...` once and the next listeners still run. A pooled tween forgets its listeners when it is freed.

- The core and backend jars embed JavaCV 1.5.9, the Java classes of FFmpeg 6.0, JSVG, TwelveMonkeys WebP, ASM 9.2, Gson 2.14.0, Guava 33.7.2, Commons IO 2.22.0 and Commons Lang 3.21.0; all but JavaCV and FFmpeg are relocated under `dev.joid.shaded.*` (`gson`, `guava`, `commons.io`, `commons.lang3`...), `org.bytedeco` is not. They no longer clash with the versions of the host, and `./gradlew checkJars` checks that no class refers to an original package.
- The FFmpeg natives are no longer embedded (about 82 MB less in every jar). Without any call, the first video downloads `org.bytedeco:ffmpeg:6.0-1.5.9:<platform>` (17 to 22 MB) from Maven Central or the repository given to `VideoNatives.repository(...)`, checks its SHA-256, and extracts its libraries once into `<cache folder>/ffmpeg/6.0-1.5.9-<platform>/`, shared by every application of the machine. Only `windows-x86_64`, `linux-x86_64`, `macosx-x86_64` and `macosx-arm64` have natives. A natives jar on the classpath wins and nothing is downloaded. `VideoNatives.install()` starts the same download when the application chooses, for example at launch behind a loading screen, and returns a `CompletableFuture<Void>`; the first video then finds the natives ready. When the download fails, each video fails with a `VideoNativesException` given to `onError`, JOID prints one `[JOID]` warning, and the next video tries again.
- `joid-core` and each `joid-backend-*` come in three jars: `-prod` to ship (no dev tool, demo or snapshot class), `-dev` for application and mod developers (inspector, hot reload, profiler, warnings and their font, the snapshot backends to test their own UIs with `joid-tool-testkit`; no demo), `-demo` for the development of JOID and of backends only (the dev tools plus the demo UIs and assets and the demo windows). `./gradlew build` builds the three.
- JOID writes in two folders only: the data folder (per application: `@UIProperty` files, `PERMANENT` stores) and the cache folder (per machine: MSDF atlases, copies of the videos that are not files, LWJGL 2 natives, FFmpeg natives, snapshot downloads), managed by `FileCache`: each area keeps an entry for its retention after its last use (7 days for the video copies, named after the SHA-1 of their content and reused by every resource and every launch that plays the same video; 30 days for the atlases, keyed by the version of JOID, and for the natives, keyed by the version of FFmpeg or LWJGL), and `JOID.load()` cleans every area of the folder once, in the background. The `Backend` setting wins over the system property, which wins over the default; folders are created only when something is written.
- JOID turns its dev mode on when the dev classes are in the jar (`-dev`, `-demo`) and its demo mode when the demo classes are (`-demo`); there is no setter any more.
- The build runs two workers at once (`--max-workers` to change it).
- `./gradlew testDemoJar testProdJar` start JOID from the `-demo` and `-prod` jar of each backend in a JVM of its own, on a hidden window (a pbuffer and the testkit window bridge for LWJGL 2), and draw a UI; the GitHub build on `main` runs `./gradlew build checkJars testDemoJar testProdJar` under Xvfb with Mesa.
- `checkJars` also checks that `NOTICE` credits each embedded library (ASM is now credited), that ASM is relocated, and that each jar holds `META-INF/LICENSE`, `META-INF/NOTICE` and the version of JOID in `dev/joid/internal/joid.properties`.
- `./gradlew build` installs the Git hooks only outside a continuous integration (`CI` unset) and only when they changed; `./gradlew updateSnapshots` at the root replaces the references of LWJGL 2, LWJGL 3 and Vulkan one backend after the other.
- Backend template: `attachInput()` is empty, so `register()` works before the input is wired; `BitmapFontContractTest` joins the contract tests; the README names the `main` of `runDemo` among the things to rename and links to [Writing a backend](https://documentation.joid.dev/build/writing-a-backend/).

## Migration checklist

1. **Dependencies**: switch to the `joid-backend-*`/`joid-base-*` artifacts and group `dev.joid`, remove `javacv`, `javacpp`, `ffmpeg`, `commons-compress`, `guava`, `gson`, `commons-lang3`, `commons-io` and `vecmath` (keep a library only when your own code uses it). On LWJGL 2, drop the `native` folder and call `Lwjgl2Natives.install()`, `Display.create()`, then `Lwjgl2Backend.create().register()`; on LWJGL 3 `Lwjgl3Backend.create(window).register()`, then `backend.frame()` in the loop; on Vulkan `VulkanBackend.create(window, host).register()` with `host = VulkanWindowHost.create(window)`, then `host.beginFrame()`, `backend.frame()`, `host.endFrame()` in the loop and `backend.destroy()`, `host.destroy()` at the end (or your own `IVulkanHost` when the application already drives Vulkan); without `JOID.inst().load()`, input forwarder or resize callback. Use the `-dev` jar for the dev mode and remove the `setDevMode`/`setDemoMode` calls. Videos need nothing more: JOID downloads the FFmpeg natives at the first video; call `VideoNatives.install()` to download them earlier, for example at launch, or put `org.bytedeco:ffmpeg:6.0-1.5.9:<platform>` on the classpath to avoid any download. See [Installation](../getting-started/installation.md).
2. **Packages**: rename the imports, then fix the classes that moved inside the library (fonts, `ResourcePlayerNode`, decoders, `RoundedShaderType`, `CoreShader`).

   ```bash
   grep -rl "be\.zeldown\.joid" src | xargs sed -i -E 's/be\.zeldown\.joid\.impl\.(lwjgl2|lwjgl3|vulkan)/dev.joid.backend.\1/g; s/be\.zeldown\.joid\.impl\.(glfw|openal)/dev.joid.base.\1/g; s/be\.zeldown\.joid/dev.joid/g'
   ```

3. **Fonts**: `MsdfFontLoader.load(new File("Inter-Regular.ttf"), new File("Inter-Bold.ttf")).thenAccept(font -> this.inter = font)`, then `TextInfo.create(this.inter, 16F)` or `TextInfo.create(this.inter, FontWeight.BOLD, 16F)`. Regenerate old atlases with the [MSDF generator](../fonts/custom-fonts.md) or load the `.ttf`. Replace `InternalFont` with your own font.
4. **Text**: convert `letterSpacing` to a fraction and `lineHeight` to a multiple of the font size (or `0`), remove `§`/`[#...]` codes or register an `ITextMarkup`, split `align(h, v)`. Check `UPPER_CAMEL_CASE` and multi-element texts with modifiers.
5. **Coordinates and zoom**: move to `ui.getView()` and `ui.getView().zoom(z)`; to scale from the host, override `IUIBridge.getInterfaceScale(UI)`. See [Canvas and Scaling](../concepts/canvas.md).
6. **Setters**: split every multi-property setter ([Nodes](#nodes), [Controls and text fields](#controls-and-text-fields)); `progress(min, max, v)` becomes the fraction; `borderFill(false)` for open corners.
7. **Signals**: replace `getOrDefault()` with `get()`/`peek()`; `subscribe`/`unsubscribe`/`publish` with `onChange`/`removeOnChange`/`fireChange` (the listeners return nothing); `control.signal(s)` with the value setter (`checked(s)`, `value(s)`, `text(s)`...); turn `UIStore.load(JsonObject)`/`save(JsonObject)` into `fromJson(String)`/`toJson()`; move each `watch(signal)` + `onInit` refresh into the setter expression; replace `WatchProperty.RELOAD` with `CLEAR_CHILDREN, BODY` and a `body(...)`; keep `watch` only for structure changes.
8. **Text fields**: replace `filter` with `accept`/`format`, migrate `onChange` to `event -> event.getText()`/`getValue()`/`isValid()`, treat `getValue()` as nullable, react to commits in `onSubmit` and on blur if needed.
9. **Controls, effects, layouts**: `SwitchNode.states/state`, `SelectorNode<V>` with `option(V)` and `values(...)`, sliders with `values(...)`/`range(...)` then `value(...)`, effects without type argument, `self(node -> node.effect(...))`, swap the `RoundedNodeEffect` sides, `xAxis`/`yAxis`, `getReorderedNode()`/`lock(...)`, slider `thumb`, remove `pipeLineLevel`.
10. **Video**: `VideoPlayerNode` → `ResourcePlayerNode`, `getDecoder()` → `getPlayback()`, `onEnd` for `stop()` → `onStop`.
11. **Resources**: decoder constructors or `ResourceFormat.decoder(...)`, `onError`/`isFailed` instead of `try`/`catch`, `onLoad` instead of the `of(input, callback)` callback, `fail(...)` in custom decoders, sprite size in `textureCoords`, `IAssetLocator` for custom inputs, `loop(true)` for GIFs that must loop, `reload()` on each builder, `MemoryResourceCache.create().size(...).expiry(...)` or your own `IResourceCache` instead of a Guava cache, `Point.create(x, y, z)` for `location(...)` and the listener position.
12. **Input**:
    - `aspectRatio(h / w)` becomes `aspectRatio(w / h)`; test `getCallbackList(...).isEmpty()`; remove duplicate callbacks that relied on being ignored.
    - Give `interactive(false)` to every sibling drawn over a clickable, hoverable, draggable or scrollable node.
    - Replace `isHovered(x, y)` with `isHovered()` and overrides with `computeHovered()`.
    - Split key hooks into `keyPressed(Key)` and `charTyped(int)`; `getLastCodepoint()`.
    - Move every listener to `event -> ...` and the new names of [Events](#events); turn the `pre` phases that refused into `beforeX(event -> event.cancel())` and the `post` phases that consumed into `handleX(event -> event.consume())`; override `mousePressed(NodeMouseEvent<?>)`... in custom nodes and test `event.isConsumed()`.
    - Take wheel values as `double` notches on two axes; rename `setScroll*` to `scrollRatio*`/`scrollOffset*`; move infinite loading to `onScrollToEnd`.
13. **UIs and bridges**:
    - Move `preDraw`/`postDraw`/`drawBackground` into a node with `onDraw` in `init()`, with a `zindex` (`Integer.MAX_VALUE` for over everything), `interactive(false)` and, for window-sized drawing, `x(this::getViewX)`, `y(this::getViewY)`, `width(this::getViewWidth)`, `height(this::getViewHeight)`; per-frame work goes to `update()`.
    - Add `@UIData(background = true)` to keep the dimmed backdrop, e.g. on modal popups.
    - Remove `@UIData(pause)`; replace `Optional` handling of `UIDataObject.get(...)` with a `null` check and `setZlevel` ordering with `setZindex`.
    - Remove the `getInstance()` override and a trivial `isOnTop(UI)`; make sure a bridge accepts each opened UI.
    - Replace `keybind(runnable, Key.LEFT_CONTROL, Key.S)` with `Shortcut.create(Key.S).ctrl(true).onTrigger(event -> runnable.run()).attach(this)`, and `schedule(runnable, delay, period)` with `Task.create(delay).every(period).onRun(event -> runnable.run()).attach(this)`.
    - Replace a `close()` override with `beforeClose(event -> event.cancel())` (or `onClose(...)` for the clean-up), and the input overrides of a UI with `handleMousePressed(...)`... registered in `init()` or the constructor.
    - Hosts: forward `keyPressed(Key)` and `charTyped(int)` separately, `mouseMoved()` on every move, `mouseReleased(MouseButton.from(button))`, wheel in notches, and read each returned `boolean`.
    - Give an id to `PERMANENT` stores that had none, rename `StoreContext` to `StoreScope`.
14. **Shaders, drawing, animation**: `Point.create(x, y)` for every `Vector2d`/`Vector2f`, two points for a gradient direction, a `BoundingBox` for a gradient canvas, `bind(ShaderPassContext)` with premultiplied output, `uniform(...)`/`sampler(...)`, `getModelView()`/`getProjection()`/`getState()`, `BlendState.NORMAL`, drop `ITransformOperation.reset()`, `Rotation.ROLL`, `translate` after `start`, paired `bind`/`unbind` (or `fill(...)`), use the equation returned by `s`/`a`/`p`, test `getTimeline() == null`, start animators from UI code or call `update()` yourself, drop the `animate(...)` calls that only advanced an animator, read animators with `get()`, one animator per value, tween callbacks as `onStart(...)`... `onComplete(...)` listeners.
15. **Backend implementers**: extend `RenderBridge`, core `Shader` and `Texture`; implement the frame and clear hooks, `drawPrimitive`, `compileProgram`, depth attachments, real mipmaps, 1-pixel lines and normalized lighting; on OpenGL register `GlRenderBridge.create(...)`; update tests to `dev.joid.test.*` and record new snapshots. See [Writing a Backend](../integration/writing-a-backend.md).
16. **Renames**: apply every table above on whole words, then organize imports in the IDE.
17. **Behaviour**: run the UIs and check the bullets under each area, above all mouse targets, `onChange` of controls and fields, Escape, shortcuts, drag and drop, wheel chaining, `zindex` order, text wrapping, `drawBorder` corners, 3D model orientation and stores.

- **Resources and media**: collected textures released on the render thread; `seek(...)` shows its frame, paused or playing; `restart()` fires `onPlay`; `UrlAsset` fallback to `http:`; `ObjModel` parsing; a looping video whose audio starts before zero (WebM with Opus, AAC in Matroska) loops instead of stalling at its end, keeps its sound after each loop and seek, and plays no sample dated before its start; collected textures released on the render thread; `seek(...)` shows its frame, paused or playing; `restart()` fires `onPlay`; `UrlAsset` fallback to `http:`; `ObjModel` parsing.
- **State and color**: `Color.decode("#RRGGBBAA")` round-trips; `Color.bind(...)` restores the previous color; `StringSignal.append` on an empty signal; a failing signal listener no longer stops the next ones; listeners run in the order they were added; adding a listener from another thread during a notification no longer throws `ConcurrentModificationException`; `silent()` no longer stays armed on a `TweenAnimator` whose value did not change; collection signals never publish `null`; `reset()` returns to the value given to the constructor; a value derived from a collection signal follows every change; stores and properties survive an exit without closing the UIs.
- **OpenGL**: registering the backend without a current context gives the `No OpenGL context is current` message instead of a JVM crash (LWJGL 3) or a raw LWJGL exception (LWJGL 2): `IGlBinding.getString` returns `null` without a context.
- **Messages**: every exception and warning of JOID says what is wrong, the value in cause and what to do (`OpenAL cannot open the default audio device, check that an audio output device is connected and enabled`); the stubs of the backend template name the method to implement.
- **Animation**: nested timelines, rewinds, repeats and yoyos; pooled tween limits; two-point `CatmullRom`.
