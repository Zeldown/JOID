# 6.2.1 — 2026-04-29

Corrections de bugs, registre extensible de resolvers de resources, et renommage de dossier pour la clarté.

## Points clés

- **Restauration de l'état GL dans `ShaderPipeline`** — Corrige les carrés blancs qui apparaissaient dans les nœuds ayant un effet shader scope `SELF` avec des enfants texturés (par exemple un `RectNode` arrondi contenant un `ResourceNode`).
- **Registre de resolvers `Resource`** — `Resource.of(Object)` est désormais extensible : enregistrez de nouveaux resolvers pour des types d'input custom sans toucher à `Resource`.
- **`assets/test` → `assets/demo`** — Renommage du dossier + références build/doc mises à jour. Les jars de production excluent maintenant correctement les assets de démo.

## Fonctionnalités

### Registre de resolvers Resource

- **[`IResourceResolver`](../resources/resolvers.md)** — Nouvelle interface. `supports(Object)` + `resolve(builder, input, callback)` — le premier match dans le registre traite l'appel.
- **`ResourceResolver.register(IResourceResolver)`** — Ajoute un resolver en tête de queue (le plus récent gagne pour les inputs que les deux peuvent matcher).
- **Resolvers intégrés** — `InputStreamResourceResolver`, `BufferedImageResourceResolver`, `UrlResourceResolver`, `TextureIdResourceResolver`. Enregistrés automatiquement.
- **`Resource.of(Object)` / `Resource.of(Object, Consumer<Resource>)`** — Point de dispatch unique. Remplace les overloads par type `of(InputStream)`, `of(BufferedImage)`, `of(String)`, `of(int)`.
- **`ResourceBuilder.compute(uniqueId, supplier)` / `compute(uniqueId, supplier, onCreate)`** — Hook public pour que les resolvers construisent des `Resource` cachées. La forme 3-args ne tourne `onCreate` qu'au cache miss — des appels `Resource.of(sameInput)` concurrents partagent le load in-flight.

### Renommage des assets

- **`assets/test/` → `assets/demo/`** — Nommage plus précis ; ces assets alimentent les classes `UIDemo*`, pas des tests unitaires.
- **`build.gradle`** — `prod.jar` exclut désormais correctement `assets/demo/*` (l'ancienne règle `assets/test/*` ne matchait plus rien après le renommage).
- **`README.md` et docs d'installation** — Mises à jour pour référencer le nouveau path.

## Corrections

- **Restauration de l'état GL dans `ShaderPipeline`** — Les flags `GL_TEXTURE_2D` et `GL_BLEND` sont désormais sauvegardés au début de `renderMultiPass` et restaurés après la passe finale. Avant, le `drawTexturedQuad` final laissait `GL_TEXTURE_2D` et `GL_BLEND` désactivés, ce qui cassait tout enfant texturé rendu après un effet shader scope `SELF`.

  Symptôme avant correction : un `RectNode` avec `RoundedNodeEffect` + `BorderNodeEffect` contenant un `ResourceNode` affichait la ressource en carré blanc.

- **Double-download au cache hit dans `UrlResourceResolver`** — Le callback `onCreate` ne tourne qu'au cache miss, donc des appels `Resource.of(sameUrl)` concurrents pendant un download in-flight ne lancent plus de downloads parallèles.

## Refactors

- **Les resolvers de Resource retournent `ResourceData`, pas `Resource`** — Le constructor de `Resource` reste `protected` ; la seule façon publique de créer un `Resource` reste `Resource.of(...)`. Les resolvers fournissent un `Supplier<ResourceData>` à `builder.compute(...)` et le builder construit le `Resource`.
- **Callback `onMiss` renommé en `onCreate`** — Plus précis : le callback tourne dès qu'un nouveau `Resource` est construit (cache miss ou pas de cache), pas seulement au miss.
- **`EffectScope` renommé en `NodeEffectScope`, déplacé comme inner de `NodeEffect`** — Nommage et namespacing plus serrés. Import : `NodeEffect.NodeEffectScope`.

## Migration depuis 6.2.0

### Breaking changes

- **`Resource.of(InputStream)` ne déclare plus `throws IOException`.** Retirez le `try/catch` autour des loads par stream :

  ```java
  // avant
  try {
      Resource res = Resource.of(myStream);
  } catch (IOException e) { ... }

  // après
  Resource res = Resource.of(myStream);
  ```

  Tous les autres usages `Resource.of(...)` compilent tels quels — le nouveau `of(Object)` accepte n'importe quel input via auto-boxing/widening.

- **`EffectScope` → `NodeEffect.NodeEffectScope`.** Mettez à jour vos imports si vous référenciez l'enum directement :

  ```java
  // avant
  import be.zeldown.joid.lib.ui.node.effect.EffectScope;

  // après
  import be.zeldown.joid.lib.ui.node.effect.NodeEffect.NodeEffectScope;
  ```

- **Builders `Resource` custom** — Si vous aviez écrit une sous-classe ou factory custom qui appelait `new Resource(...)` depuis hors du package `lib.resource`, basculez sur un resolver : implémentez `IResourceResolver`, enregistrez-le une fois, et laissez `Resource.of(monInput)` dispatcher.

### Ajouts (non-breaking)

- Les appels existants `Resource.of(stream)`, `Resource.of(image)`, `Resource.of(url)` continuent de fonctionner — ils sont désormais routés via le registre de resolvers.
