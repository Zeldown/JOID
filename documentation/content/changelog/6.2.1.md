# 6.2.1 — 2026-04-29

Bug fixes, an extensible resource resolver registry, and a folder rename for clarity.

## Highlights

- **`ShaderPipeline` GL state restore** — Fixes white squares appearing inside nodes that had a `SELF`-scoped shader effect with textured children (e.g., a rounded `RectNode` containing a `ResourceNode`).
- **`Resource` resolver registry** — `Resource.of(Object)` is now extensible: register new resolvers for custom input types without touching `Resource` itself.
- **`assets/test` → `assets/demo`** — Folder rename + build/doc references updated. Production jars now correctly exclude demo assets.

## Features

### Resource resolver registry

- **[`IResourceResolver`](../resources/resolvers.md)** — New interface. `supports(Object)` + `resolve(builder, input, callback)` — first match in the registry handles the call.
- **`ResourceResolver.register(IResourceResolver)`** — Adds a resolver to the front of the queue (most recent wins for inputs both can match).
- **Built-in resolvers** — `InputStreamResourceResolver`, `BufferedImageResourceResolver`, `UrlResourceResolver`, `TextureIdResourceResolver`. Registered automatically.
- **`Resource.of(Object)` / `Resource.of(Object, Consumer<Resource>)`** — Single dispatch point. Replaces the per-type `of(InputStream)`, `of(BufferedImage)`, `of(String)`, `of(int)` overloads.
- **`ResourceBuilder.compute(uniqueId, supplier)` / `compute(uniqueId, supplier, onCreate)`** — Public hook for resolvers to build cached `Resource`s. The 3-arg form runs `onCreate` only on cache miss — concurrent `Resource.of(sameInput)` calls share the in-flight load.

### Asset rename

- **`assets/test/` → `assets/demo/`** — More accurate naming; these assets feed the `UIDemo*` classes, not unit tests.
- **`build.gradle`** — `prod.jar` now correctly excludes `assets/demo/*` (the previous `assets/test/*` rule no longer matched anything after the rename).
- **`README.md` and installation docs** — Updated to reference the new path.

## Fixes

- **`ShaderPipeline` GL state restore** — `GL_TEXTURE_2D` and `GL_BLEND` enabled state is now saved at the start of `renderMultiPass` and restored after the final pass. Previously, the final `drawTexturedQuad` left `GL_TEXTURE_2D` and `GL_BLEND` disabled, which broke any textured child rendered after a `SELF`-scoped shader effect.

  Symptom before the fix: a `RectNode` with `RoundedNodeEffect` + `BorderNodeEffect` containing a `ResourceNode` showed the resource as a white square.

- **`UrlResourceResolver` cache hit double-download** — The `onCreate` callback only runs on cache miss, so concurrent `Resource.of(sameUrl)` calls during an in-flight download no longer spawn parallel downloads.

## Refactors

- **Resource resolvers return `ResourceData`, not `Resource`** — `Resource`'s constructor stays `protected`; the only public way to create a `Resource` remains `Resource.of(...)`. Resolvers feed a `Supplier<ResourceData>` to `builder.compute(...)` and the builder constructs the `Resource`.
- **`onMiss` callback renamed to `onCreate`** — More accurate: the callback runs whenever a new `Resource` is constructed (cache miss or no cache), not just on miss.
- **`EffectScope` renamed to `NodeEffectScope`, moved as inner of `NodeEffect`** — Tighter naming and namespacing. Import: `NodeEffect.NodeEffectScope`.

## Migration from 6.2.0

### Breaking changes

- **`Resource.of(InputStream)` no longer declares `throws IOException`.** Remove the `try/catch` around stream-based loads:

  ```java
  // before
  try {
      Resource res = Resource.of(myStream);
  } catch (IOException e) { ... }

  // after
  Resource res = Resource.of(myStream);
  ```

  All other `Resource.of(...)` usages compile unchanged — the new `of(Object)` accepts any input via auto-boxing/widening.

- **`EffectScope` → `NodeEffect.NodeEffectScope`.** Update your imports if you referenced the enum directly:

  ```java
  // before
  import be.zeldown.joid.lib.ui.node.effect.EffectScope;

  // after
  import be.zeldown.joid.lib.ui.node.effect.NodeEffect.NodeEffectScope;
  ```

- **Custom `Resource` builders** — If you wrote a custom subclass or factory that called `new Resource(...)` from outside the `lib.resource` package, switch to a resolver: implement `IResourceResolver`, register it once, and let `Resource.of(myInput)` dispatch.

### Additions (non-breaking)

- Existing `Resource.of(stream)`, `Resource.of(image)`, `Resource.of(url)` calls keep working — they're now routed through the resolver registry.
